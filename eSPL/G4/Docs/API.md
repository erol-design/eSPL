## stm32g4_adc.h

ADC driver for STM32G4 (RM0440 Rev 9 chapter 21): ADC1/ADC2 on every SKU, ADC3/ADC4/ADC5 where CMSIS defines them. Common registers per pair block (ADC12_COMMON / ADC345_COMMON). Scope: regulator, calibration, enable/disable, regular group (sequence, sampling, trigger, DMA request), oversampling, analog watchdog 1, internal channels, differential inputs. Not implemented: injected group, dual mode, AWD2/3, offsets, gain compensation (fields kept). Usage: ADC_PowerRegulator, wait tADCVREG_STUP, ADC_StartCalibration / ADC_CalibrationDone, wait 4 ADC clocks, configuration (ADC_CommonClockConfig, ADC_RegularConfig, ADC_RegularSequenceConfig, ADC_SetSamplingTime, ...), ADC_Enable / ADC_Ready, then ADC_Start and ADC_TryRead (or DMA); ADC_StopRegular / ADC_RegularStopped, ADC_Disable / ADC_Disabled. Common rules: no static state, no function waits (start + poll design); no register write on error; output parameters are unchanged unless SPL_OK (METHOD 1.8). Caller duties (all APIs; not done by the driver):  - Clock: RCC bus clock of the ADC pair and, with ADC_CLOCK_ASYNC, the ADC kernel clock.  - Pins: input GPIOs in analog mode; do not select channels not bonded on the package.  - Timing: tADCVREG_STUP after ADC_PowerRegulator, 4 ADC clocks after ADCAL clears before    ADEN, sensor start-up times (datasheet); bound every *Ready / *Done / *Stopped /    *Disabled poll with a caller timeout.  - Trigger source (timer TRGO, EXTI), DMA channel, NVIC and handlers when used; while    DMAEN = 1 the DMA owns DR (do not call ADC_TryRead).  - Serialize calls per ADC instance and common-block APIs per pair (ISR included).  - Errata CALLER items: REV_ID via DBGMCU_GetIdCode (0x2001 Rev Z, 0x2002 Rev Y, 0x2003 Rev X;    G491/G4A1: 0x1000 Rev A, 0x1001 Rev Z); G411/G414 have no errata sheet, assume the items    may apply. Items (ES0431 2.5.x = ES0430 2.7.x Rev 10; ES0523 2.6.x Rev 7) at the APIs below. Contract: Docs/v0.11_ADC_CONTRACT.md (sections "Errata", "Caller notes").

### `ADC_Start`

```c

```

Pending ADDIS/ADSTP/JADSTP: BUSY, no register writes. ADSTART=1: BUSY in single mode with software trigger (clears at EOS); v0.11.1: ERR_STATE with CONT=1 or EXTEN!=0 (never clears by itself; ADC_StopRegular first). ERRATA ES0431 2.5.9 / ES0430 2.7.9 / ES0523 2.6.7: a conversion > 1 ms after calibration or the previous conversion may be wrong (all revisions); convert twice, drop the first.

- Caller: with EXTEN != 0 OK means armed only (completion via EOC/EOS); after calibration, ADC_Enable or a gap > 1 ms drop the first conversion (errata above); with DMA enable the DMA channel first.

### `ADC_TryRead`

```c
SPL_Status ADC_TryRead(ADC_TypeDef *adc, uint16_t *value);
```

- Caller: on OVR (ERR_HW here, or the OVR flag) the library restarts nothing; the caller clears OVR (ADC_ClearErrors) and restarts the conversion and, when DMA is used, the DMA channel. OVR: ERR_HW. EOC=0: disabled -> ERR_STATE; enabled and ADSTART=1 -> WOULD_BLOCK; v0.11.1: enabled and ADSTART=0 (nothing running, sample already read, stopped) -> ERR_STATE. Retained EOC data can be read after disable. Error leaves output unchanged. not while DMAEN = 1 (the DMA owns DR); differential results are offset binary (0x800 at zero difference, 12 bit), signed conversion is the caller's.
- Level: `PARAM[F] STATE[r] HW[r] WOULD_BLOCK[r]`

### `ADC_EnableDma`

```c

```

- Caller: the library does not link the ADC sequence to the DMA channel. The caller maps buffer index n to sequence rank n, sets the DMA count to a multiple of the sequence length, enables the DMA channel before ADC_Start, and with repeated scans uses circular here and DMA circular together (or re-arms ADC and DMA after each one-shot sequence). ## stm32g4_comp.h

Analog comparator driver for STM32G4 (RM0440 Rev 9 section 24): COMP1..COMP7 as present in CMSIS (G431: COMP1..4). One register per instance (COMP_CxCSR). Scope: input selection, hysteresis, polarity, blanking, enable/disable, output read, LOCK. No interrupt or EXTI configuration. Usage: COMP_Config (comparator disabled), COMP_Enable, wait the start-up time, then COMP_GetOutput; COMP_Disable before reconfiguring; optional COMP_Lock. Common rules: no static state, no function waits; output parameters are unchanged unless SPL_OK (METHOD 1.8). LOCK: once CSR.LOCK is set the register is read-only until system reset (RM0440 24.3.4); every API that would write CSR then returns SPL_ERR_STATE and writes nothing. Caller duties (all APIs; not done by the driver):  - Clock: SYSCFG clock in RCC (COMP has no own enable bit, RM0440 24.3.3).  - Pins: GPIO inputs in analog mode, output pin in alternate function (RM0440 24.3.2).  - Start-up: after COMP_Enable wait the comparator start-up time and, when a VREFINT input is    used, the VREFINT scaler start-up time from the datasheet before trusting the output.  - Interrupt / wake-up: EXTI line of the comparator (EXTI driver, RM0440 24.5).  - Serialize calls per instance (ISR included). Contract: Docs/v0.11_COMP_CONTRACT.md.

### `COMP_Config`

```c
SPL_Status COMP_Config(COMP_TypeDef *comp, const COMP_ConfigTypeDef *config);
```

LOCK=1: STATE. EN=1: STATE. Writes the whole CSR with EN=0, LOCK=0. ERRATA ES0431 2.6.1 / ES0430 2.9.1 (Rev Z, Y; not Rev X; not in ES0523, G491/G4A1 free): Voffset -20..+3 mV (typ -15/+2) replaces the datasheet value; no workaround, budget it in thresholds.

- Caller: disable first (COMP_Disable); on Rev Z/Y budget the errata Voffset in the INMSEL / DAC threshold and hysteresis.
- Level: `PARAM[F] STATE[r] UNSUPPORTED[r]`

### `COMP_Enable`

```c
SPL_Status COMP_Enable(COMP_TypeDef *comp);
```

LOCK=1: STATE. Sets EN; other bits unchanged. Does not wait for start-up.

- Caller: COMP_Config first; wait the start-up time(s) (file header) before reading the output.
- Level: `PARAM[F] STATE[r]`

### `COMP_Disable`

```c
SPL_Status COMP_Disable(COMP_TypeDef *comp);
```

LOCK=1: STATE. Clears EN; other bits unchanged.

- Caller: none beyond the file-header duties.
- Level: `PARAM[F] STATE[r]`

### `COMP_GetOutput`

```c
SPL_Status COMP_GetOutput(const COMP_TypeDef *comp, uint8_t *level);
```

VALUE: comparator output before polarity and blanking (RM0440 24.6.1). EN=0: STATE.

## stm32g4_cordic.h

CORDIC coprocessor driver (RM0440 Rev 9 section 17). Scope: the single CORDIC instance on every supported SKU; integer only; q1.15 pack helpers. Usage: CORDIC_ContextInit, CORDIC_Config, then CORDIC_TryWrite / CORDIC_TryRead pairs (polling), or CORDIC_InterruptConfig / CORDIC_DmaConfig for those modes. Common rules: no function waits; no static state (outstanding-operation count lives in the caller's CORDIC_ContextTypeDef); no clock is enabled here. Arguments are written pre-scaled and results are returned raw (RM0440 17.3.4). The driver never reads CORDIC_RDATA before RRDY=1, so the AHB bus is never stalled (17.3.7). Caller duties (all APIs):  - Clock: AHB clock RCC_AHB1ENR.CORDICEN before any call (RCC module).  - State: one caller-owned CORDIC_ContextTypeDef shared by all calls.  - Values: scale arguments before writing and undo the scaling on results (multiply phase    results by pi, etc.); the driver does no arithmetic on values.  - Concurrency: not reentrant; serialize callers. With IEN=1 the ISR owns the result path    (thread code then does not call CORDIC_TryRead). Contract: Docs/v0.13_CORDIC_CONTRACT.md.

### `CORDIC_ContextInit`

```c
SPL_Status CORDIC_ContextInit(CORDIC_ContextTypeDef *ctx);
```

outstanding = 0. No register access.

- Caller: call once before first use and after a CORDIC reset; a stale RRDY is drained with CORDIC_TryRead.
- Level: `PARAM[F]`

### `CORDIC_Config`

```c
SPL_Status CORDIC_Config(const CORDIC_ContextTypeDef *ctx, const CORDIC_ConfigTypeDef *config);
```

One CSR write (IEN kept, DMA bits 0). PARAM: NULL or field rule broken (see contract). STATE: DMA enabled, RRDY=1, or outstanding != 0.

- Caller: after a function change with 32-bit arguments write ARG2 explicitly (arg_writes = 2) for the first calculation (ARG2 value after a FUNC change is not specified, contract O4; not enforced).
- Level: `PARAM[F] STATE[r]`

### `CORDIC_InterruptConfig`

```c
SPL_Status CORDIC_InterruptConfig(uint8_t enable);
```

IEN = enable (interrupt while RRDY=1). Other fields kept.

- Caller: NVIC priority / enable of CORDIC_IRQn and its handler, which reads the result (CORDIC_TryRead) to clear RRDY.
- Level: `PARAM[F]`

### `CORDIC_DmaConfig`

```c
SPL_Status CORDIC_DmaConfig(const CORDIC_ContextTypeDef *ctx, uint8_t read_enable, uint8_t write_enable);
```

DMAREN/DMAWEN. Entering DMA mode needs outstanding=0 and RRDY=0 (STATE). DMAWEN=1 requests data at once.

- Caller: configure the DMA / DMAMUX channels first; disable DMA mode only after the channels completed (the context does not count DMA-started calculations, contract O3).
- Level: `PARAM[F] STATE[r]`

### `CORDIC_TryWrite`

```c
SPL_Status CORDIC_TryWrite(CORDIC_ContextTypeDef *ctx, uint32_t wdata1, uint32_t wdata2);
```

Writes the arguments of one calculation (starts it or queues it). 32-bit: wdata1 = ARG1, wdata2 = ARG2 (written only when NARGS=1). 16-bit: wdata1 = ARG1 [15:0] | ARG2 [31:16], wdata2 ignored. PARAM: NULL or argument outside the RM range for FUNC/SCALE. STATE: DMA enabled, two operations outstanding (read first), or CSR not a valid configuration.

## stm32g4_fdcan.h

FDCAN driver (RM0440 Rev 9 section 44): Message RAM configuration, acceptance filters, RX FIFO read / acknowledge, TX FIFO / queue add / cancel, CAN FD / BRS and data timing, IRQ routing. Instances: FDCAN1, plus FDCAN2/FDCAN3 only where CMSIS defines them; any other pointer -> SPL_ERR_PARAM. Message RAM layout fixed per instance (stm32g4_fdcan_layout.h, FD-01). Common rules: no function waits, no static mutable state; status order PARAM -> STATE -> WOULD_BLOCK / ERR_HW, and any non-OK result writes no register, Message RAM or output. Protected configuration (Configure, SetDataTiming, SetTestMode, SetNominalTiming) needs INIT = 1 and sets CCE itself; CCE resets RXFxS, TXFQS, TXBRP, TXBTO, TXBCF. Usage: RequestInit -> InitReady==1 -> SetNominalTiming -> Configure -> [SetDataTiming] -> filters -> [SetTestMode] -> LeaveInit -> InitReady==0 -> TryWrite/TryRead. INIT crosses clock domains and reads back late (RM0440 44.4.6 CCCR note): until InitReady reports 0 after LeaveInit, TryWrite/TryRead return STATE for the stale INIT=1. ## stm32g4_flash.h

Embedded flash interface for STM32G4 (RM0440 Rev 9 sections 3, 4 and 5). Scope: wait states and accelerator, geometry, unlock / lock, page erase, double-word program and ECC diagnosis. Option-byte programming is out of scope (OPTR is only read). Usage: FLASH_Unlock, FLASH_ClearFlags (pending errors), FLASH_ErasePageStart / FLASH_ProgramDoubleWordStart, poll FLASH_PollOperation until OK, FLASH_EndOperation after the last operation, then FLASH_Lock. Common rules: single FLASH instance, no dynamic memory, no static state; no function waits (program / erase only start the operation, BUSY is returned instead). Every API that writes CR checks BSY first (a CR write while BSY=1 stalls the AHB bus, RM0440 3.3.6). Output parameters are written only on OK. FLASH_PollOperation and FLASH_GetFlags are read-only. Executing code or reading data from the bank that is being erased or programmed stalls the bus (CPU) until the operation ends (RM0440 3.3.6). Single-bank parts always stall unless the caller runs from RAM. Caller duties (all APIs; not done by the driver):  - Single owner: not reentrant; serialise all FLASH calls (ISR included).  - Program / erase only in VCORE range 1 (RM0440 3.3.6; PWR is not checked here).  - Code location (CCL-2 FL-09a): budget the bus stall against the watchdog and the interrupt    latency, or place the wait loop, the handlers and the vector table in RAM (DBANK=1: in    the other bank).  - Device layer: record layout, wear levelling and power-fail handling are the caller's. Contract: Docs/v0.10_FLASH_CONTRACT.md.

## stm32g4_fmac.h

Filter math accelerator driver for STM32G4 (FMAC, RM0440 Rev 9 section 18). Scope: single instance, present on every STM32G4 SKU. FIR and IIR (direct form 1) filters with Q1.15 data; buffer layout, preload, start / stop and the polling data path. Usage: FMAC_ConfigBuffers -> FMAC_ControlConfig(0 or error IEs) -> FMAC_LoadX2 (coefficients) [-> FMAC_LoadX1 / FMAC_LoadY] -> FMAC_ControlConfig(data IEs / DMA) -> FMAC_FilterStart -> FMAC_TryWrite / FMAC_TryRead ... -> FMAC_FilterStop. ## stm32g4_fmc.h

Flexible memory controller driver for STM32G4 (RM0440 Rev 9 section 19). Scope: NOR/PSRAM/SRAM controller (bank 1, four sub-banks NE1..NE4) and NAND controller (bank 3). There is no SDRAM controller on STM32G4. FMC exists only where CMSIS defines FMC_Bank1_R (G473/G474/G483/G484); on every other SKU each API returns SPL_ERR_UNSUPPORTED without any access. RM0440 Rev 9 has no global FMC enable bit in FMC_BCR1 (bits 31:24 are reserved), unlike some other STM32 families. Usage: FMC_NORSRAM_Init (sub-bank disabled), optional FMC_PSRAM_SetCounter, then FMC_NORSRAM_Enable; NAND: FMC_NAND_Init, FMC_NAND_ITConfig, FMC_NAND_Enable, per page FMC_NAND_ECCStart -> data transfer -> FMC_NAND_GetECC. Common rules: no dynamic memory, no static state; no function waits (WOULD_BLOCK is returned instead); parameters are validated before any write; output parameters are written only on OK. Errata: ES0430 Rev 10 (G471/473/474/483/484) section 2.5; contract section "Errata". ES0431 (G431/441) has no FMC items (no FMC on those parts). ## stm32g4_hrtim.h

High-resolution timer HRTIM1 driver (RM0440 Rev 9 section 28). Present only where CMSIS defines HRTIM1 (G474/G484/G414); on every other SKU each API returns SPL_ERR_UNSUPPORTED without register access. Scope v0.14: DLL calibration, timer A..F time base (continuous / single-shot), compare units 1..4, output set/reset crossbar, polarity, idle and fault levels, positive dead time, output enable/disable, counter enable, software update/reset/force, flags. ## stm32g4_i2c.h

I2C driver for STM32G4 (RM0440 Rev 9 chapter 39): controller (master) transfers, long and 10-bit transfers (v0.10), target (slave) mode and SMBus/PEC (v0.17, last section). Scope: I2C1..I2C3 (I2C4 is not handled); the base API is a single chunk of 1..255 bytes, master, 7-bit address, nonblocking byte service; I2C_StartLong / I2C_RestartLong extend it to longer and 10-bit transfers. SMBus/PMBus, TIMEOUTR and Stop wake-up exist on I2C1 only. Usage: I2C_MasterInit, then per transfer I2C_Start (or I2C_StartNoStop / I2C_Restart), I2C_TryWrite / I2C_TryRead per byte, end with I2C_StopDetected / I2C_ClearStop (AUTOEND) or I2C_TransferComplete and I2C_Stop / I2C_Restart (software end). Common rules: no dynamic memory, no static state (long-transfer bookkeeping is caller-owned); no function waits for a flag (I2C_SoftwareReset reads PE back, I2C_TargetTimeoutRecover holds PE = 0 for three CR1 reads); output parameters are unchanged unless SPL_OK (METHOD 1.8). ERRATA ES0431 2.11.1 / ES0430 2.15.1 / ES0523 2.11.1: SDA is mis-sampled when tSU;DAT < one I2CCLK period; for spec-minimum transmitters use I2CCLK >= 4 MHz (Sm), >= 10 MHz (Fm), >= 20 MHz (Fm+) (caller's RCC kernel clock choice). ERRATA ES0431 2.11.5 / ES0430 2.15.5 / ES0523 2.11.4: TX may stall after the first byte when PCLK/I2CCLK is in 1.5..3 (the driver never prefills TXDR): keep the ratio < 1.5 or > 3 (e.g. I2CCLK = PCLK1). Target-mode errata are handled by the v0.17 target APIs below. Caller duties (all APIs; not done by the driver):  - Clock: RCC bus clock of the instance (RCC_PERIPH_I2Cx) and the kernel clock    (RCC_KERNEL_I2Cx); timingr and timeoutr values are computed for that I2CCLK frequency.  - Pins: SCL / SDA (SMBA with I2C_SMBUS_ALERT) in alternate function, open drain, with external    pull-ups; bus recovery of a stuck SDA is the board layer (see I2C_SoftwareReset).  - Retry bounds: WOULD_BLOCK / BUSY on a stuck bus repeat forever; the caller bounds them.  - No interrupt or DMA API: NVIC, handler and DMA setup are the caller's if used.  - Serialize all calls per instance (ISR included). Device-layer duties (CCL-2 driver-library hand-off; no device knowledge, no sleep entry here):  - Caller duty (CCL-2 I2C-28, I2C-29): after each write to a device with a write    cycle (e.g. EEPROM) poll its address for ACK with a bounded retry count, or wait a    fixed time, before the next command; split writes at the device page boundary.  - Caller duty (CCL-2 I2C-27): verify any checksum/CRC field the device sends before    using the data. With PEC, I2C_StopDetected, I2C_TransferComplete and the target    byte services return ERR_HW while PECERR is set (flag kept: read I2C_GetErrors,    then clear); a DMA transfer reads I2C_GetErrors itself at the end.  - Caller duty (CCL-2 I2C-30): this driver never enters a low-power mode; before    WFI/WFE make sure no transfer runs (ISR.BUSY=0, STOP sent and detected).  - Caller duty (CCL-2 I2C-24): target mode is polled and enables no interrupt; handle    every ADDR (I2C_TargetPollAddress, I2C_TargetAckAddress), STOPF (I2C_ClearStop)    and NACKF (I2C_ClearErrorFlags) event and reset the buffer index and direction on    every STOP or NACK. Contract: Docs/v0.10_I2C_CONTRACT.md; target mode and SMBus: Docs/v0.17_I2C_TARGET_SMBUS_CONTRACT.md.

## stm32g4_iwdg.h

Independent watchdog driver for STM32G4 (RM0440 Rev 9 section 35). Usage: IWDG_Start, then IWDG_SetPrescalerReload / IWDG_SetWindow (poll IWDG_UpdateStatus), then IWDG_Refresh before every timeout. Common rules: single IWDG instance, no static state, no function waits (BUSY is returned instead); output parameters are written only on OK. Once started the IWDG cannot be stopped except by a reset (RM0440 35.3.2). The hardware-watchdog option bit may start it at power-on without any software action. The library itself never refreshes. Caller duties (all APIs; not done by the driver):  - Serialize calls; never run IWDG_Refresh (KR = 0xAAAA) in another context between the    KR = 0x5555 unlock and the PR / RLR / WINR writes of IWDG_SetPrescalerReload /    IWDG_SetWindow (the reload key re-locks them).  - Caller duty (CCL-2 WDG-02a, WDG-02b): call IWDG_Refresh only from thread context, never    from an interrupt handler or a callback run by one, and only in the main (task) loop or    inside a long multi-page/multi-block processing loop, never in delay, driver or helper    functions.  - Caller duty (CCL-2 WDG-10): with several tasks or a cyclic schedule, refresh only after    every critical task has reported progress in the last refresh interval, or only after a    common cycle that called all critical tasks unconditionally has completed in that round.  - Caller duty (CCL-2 WDG-08): keep WINR below RLR (or WINR = 0xFFF, window off) and refresh    only after the counter has dropped below WINR; the library cannot read the IWDG counter    and does not check the WINR/RLR relation (separate calls, no static state).  - Caller duty (CCL-2 WDG-11): every operation without refresh after IWDG_Start (oscillator    and PLL polling, flash erase, start-up waits) must be shorter than the timeout computed at    the upper LSI tolerance from the datasheet, not at IWDG_LSI_NOMINAL_HZ; otherwise refresh    inside it or start the IWDG after it. Contract: Docs/v0.10_WDG_CONTRACT.md.

### `IWDG_Start`

```c
SPL_Status IWDG_Start(void);
```

KR=0xCCCC. Irreversible. Also starts the LSI if needed.

- Caller: from now on refresh before every timeout (no stop until reset); set the timing afterwards with IWDG_SetPrescalerReload / IWDG_SetWindow (register access needs the IWDG running, RM0440 35.3.2 order).
- Level: `-`

### `IWDG_SetPrescalerReload`

```c
SPL_Status IWDG_SetPrescalerReload(uint32_t prescaler, uint32_t reload);
```

KR=0x5555, then PR (0..7) and RLR (1..0xFFF). BUSY if PVU/RVU/WVU set.

- Caller: call after IWDG_Start; poll IWDG_UpdateStatus (bounded) until OK before relying on the new timeout or writing PR/RLR/WINR again.
- Level: `PARAM[F] BUSY[r]`

### `IWDG_SetWindow`

```c
SPL_Status IWDG_SetWindow(uint32_t window);
```

KR=0x5555, then WINR (1..0xFFF; 0xFFF disables the window). BUSY unless IWDG_SR == 0. Writing WINR also reloads the counter (RM0440 35.3.2).

- Caller: call after IWDG_Start; poll IWDG_UpdateStatus (bounded) after OK; with a window set, time every IWDG_Refresh inside the window (CCL-2 WDG-08 above).
- Level: `PARAM[F] BUSY[r]`

### `IWDG_Refresh`

```c

```

KR=0xAAAA. Outside the window this resets the MCU.

- Caller: time the call before the timeout and, with a window, inside it; the driver cannot read the counter, so a mistimed refresh is not detected (CCL-2 WDG-02a/02b, WDG-10 above).
- Level: `-`


BUSY while any of PVU/RVU/WVU is set, else OK. These bits clear only with the LSI running; LSIRDY = 0 is not reported as STATE because it is also the normal state during LSI start-up right after IWDG_Start. The update takes up to five (LSI) cycles once the LSI runs (RM0440 35.4.4).

- Caller: derate the result with the datasheet LSI tolerance (CCL-2 WDG-11 above).

## stm32g4_lptim.h

Low-power timer driver (LPTIM, RM0440 Rev 9 section 33). Scope: LPTIM1 only (the only instance on the supported SKUs; any other pointer is SPL_ERR_PARAM). LPTIM_OR input remap is not handled. ## stm32g4_qspi.h

Quad-SPI interface driver (RM0440 Rev 9 section 20). Single instance (CMSIS QUADSPI, 0xA000 1000), present only on SKUs whose CMSIS header defines QUADSPI (G471/473/474/483/484/491/4A1). On other SKUs (G431/441/411/414) the module still compiles and EVERY API returns SPL_ERR_UNSUPPORTED without any register access. Common rules: no handle, no static state, no function waits; every register write happens only after all parameter and state checks passed; CR read-modify-writes never copy the self-clearing ABORT back (while ABORT is pending a CR writer returns BUSY). The driver is a register-level command engine: flash commands, page / sector boundaries, write-enable, busy polling of the memory and its timing belong to the device layer (caller). Usage: QSPI_Init (interrupts masked on G47x/G48x, ERRATA below), QSPI_Enable, then per command QSPI_CommConfig (plus QSPI_SetAddress / QSPI_TryWrite* / QSPI_TryRead* as QSPI_GetStartTrigger reports), QSPI_GetStatus / QSPI_ClearFlags; stop with QSPI_Abort + QSPI_AbortPoll. Caller duties (all APIs): RCC AHB3 clock enable (QSPIEN) and kernel clock QSPISEL (RCC module); GPIO alternate functions of CLK / NCS / IO pins; DMA channel setup; with DMAEN = 1 disable the DMA channel before changing FTHRES or FMODE, and in indirect write write AR before enabling the DMA (RM0440 20.3.11); never access the 0x9000 0000 bank before memory-mapped mode is configured; FSIZE must cover the memory (TEF / bus fault otherwise); NVIC and handler (the handler clears TE / TC / SM / TO with QSPI_ClearFlags); serialize all callers (one owner; an ISR that services the FIFO must be the only DR user while a command runs); bound every retry loop on BUSY / WOULD_BLOCK (a FIFO that nobody services never drains, the driver cannot tell a stalled transfer from a running one). Contract: Docs/v0.12_QSPI_CONTRACT.md. Errata: ES0430 Rev 10 (G471/473/474/483/484) section 2.6 and ES0523 Rev 7 (G491/G4A1) section 2.5, contract section "Errata". ES0523 lists only the last-byte item (2.5.1); the ES0430 2.6.1 / 2.6.3 rules below are built for the ES0430 dies only (v0.13.2). ERRATA ES0430 2.6.2: CCR = 0 hangs the peripheral; every accepted command has CCR != 0 (empty command refused on every SKU). Recovery if it ever happens: EN 0->1. ERRATA ES0430 2.6.4 / ES0523 2.5.1: a memory-mapped read of the last byte of the FSIZE region returns 0x00, a repeated read stalls the AXI bus: keep margin in flash_size or read that byte in indirect mode (caller).

## stm32g4_rcc.h

Reset and clock control driver for STM32G4 (RM0440 Rev 9 chapter 7). Scope: oscillators (HSI16, HSE, LSI, HSI48; LSE is in the RTC module), PLL, SYSCLK source, AHB/APB prescalers, peripheral bus clocks and resets, kernel clock selectors, MCO, CSS, reset cause, and read-only frequency queries. Not here: PWR voltage range, FLASH latency, GPIO alternate functions (MCO and OSC pins); the RCC module does not hide any of these steps. Usage (bring-up to 170 MHz, contract section 3): enable PWR clock, RCC_SetAhbPrescaler(2), voltage range and FLASH latency (other modules), RCC_SetHseBypass / RCC_StartOsc / RCC_GetOscReady, RCC_ConfigPll / RCC_EnablePll / RCC_GetPllReady, RCC_SetSysclkSource / RCC_GetSysclkSource, wait >= 1 us, final prescalers, then per peripheral RCC_SetKernelClock and RCC_EnablePeriphClock. Common rules: no static state, no function waits on a hardware flag (start + poll); a rejected call writes no register; output parameters are written only on SPL_OK, except RCC_GetOscReady / RCC_GetPllReady (always write *ready). Frequencies are in Hz and derived from the register configuration (oscillator readiness is not checked). Caller duties (all APIs; not done by the driver):  - Serialize RCC calls with every ISR or context that also writes RCC (CR, CFGR, PLLCFGR, CSR,    CCIPR, ENR, RSTR writes are read-modify-write); Get* APIs are single reads (ISR-safe).  - hse_hz is the real HSE frequency (crystal or bypass clock; 0 = HSE unused): the driver    cannot measure it.  - Poll timeouts: the wait for every oscillator / PLL / SYSCLK switch and its timeout    (e.g. HSE start-up per datasheet) belong to the caller.  - Sequencing with PWR voltage scaling, FLASH latency and the HPRE /2 transition    (contract section 3); the driver does not check them. Errata CALLER items (ES0431 / ES0430 / ES0523, contract "Errata"): 2.2.9 Standby with HSE bypass as SYSCLK (at RCC_SetHseBypass); ES0431 2.2.3 / ES0430 2.2.4 LSI as RTCCLK (at RCC_GetResetFlags); ES0431 2.2.7 / ES0430 2.2.7 / ES0523 2.2.5 keep FLASHSMEN = 1 for Sleep with debug, or ISB after WFI/WFE; ES0431 2.2.8 / ES0430 2.2.8 / ES0523 2.2.6 keep PC13 static with an LSE crystal (board). ## stm32g4_rtc.h

RTC + backup-domain clock + TAMP (RM0440 Rev 9 sections 37, 38, 7.4.27): LSE and RTCCLK, calendar, alarms A/B, wake-up timer, timestamp, smooth calibration, RTC output, daylight saving, TAMP inputs 1..3, internal tampers 3..6 and backup registers. Usage: RTC_LSEStart / RTC_LSEReady, RTC_ClockConfig, RTC_WriteProtectDisable, RTC_EnterInit /   RTC_InitReady, RTC_SetPrescaler, RTC_SetHourFormat, RTC_SetTime / RTC_SetDate, RTC_ExitInit,   RTC_WriteProtectEnable, RTC_SyncReady, RTC_GetTimeDate; then alarms, wake-up timer,   timestamp and TAMP. Common rules: every write service requires PWR_CR1.DBP = 1 (backup-domain write access) and   returns SPL_ERR_STATE without writing otherwise. No function waits: a flag that is not set   yet gives WOULD_BLOCK / BUSY (STATE when RTCCLK is absent, see RTC_GetTimeDate). RTC_CR   read-modify-writes never write ADD1H/SUB1H back. Flag clears write only the requested W1C   bits and read the status register back. Single RTC instance, no static state. Caller duties (all APIs): RTC APB clock (RCC_APB1ENR1.RTCAPBEN) and PWR clock (RCC module);   PWR_CR1.DBP = 1 before writes; RTC_WriteProtectDisable before writing RTC registers (not   checked: RTC_WPR cannot be read and a locked RTC ignores the write; RCC_BDCR and TAMP need   only DBP); serialize all calls (ISR included); interrupts need their EXTI line and NVIC   setup (RTC_Alarm_IRQn, RTC_WKUP_IRQn, RTC_TAMP_LSECSS_IRQn), outside this driver. ## stm32g4_sai.h

## stm32g4_spi.h

SPI driver for STM32G4 (RM0440 section 42); SPI mode only, I2S mode is out of scope. Scope: SPI1, SPI2, SPI3 and SPI4 (SPI3 / SPI4 only where CMSIS defines them); legacy API (v0.8 .. v0.10) and extended configuration (v0.11). Usage: SPI_Init (or the legacy SPI_MasterInit) with SPE = 0, optional SPI_ITConfig / SPI_DmaConfig / SPI_DmaPackingConfig, SPI_Enable(spi, 1), then the Try* transfers; SPI_Enable(spi, 0) to stop. Common rules: no dynamic memory, no static state; no function waits (BUSY / WOULD_BLOCK are returned instead); not reentrant per instance; output parameters are unchanged unless SPL_OK (METHOD 1.8). Any read of SPIx_SR clears FRE by hardware (RM0440 42.9.3); every service that checks a flag reads SR. In TI slave mode capture FRE with SPI_GetErrors before calling other services. Caller duties (all APIs; not done by the driver):  - Clock: RCC bus clock and reset of the instance; prescaler values divide PCLK.  - Pins: SCK / MISO / MOSI / NSS in their GPIO alternate function; pin ownership and the    idle levels after SPI_Enable(0) are the caller's (CCL-2 SPI-16b).  - Interrupts / DMA: NVIC line, priority and handler; DMA channel / DMAMUX setup.  - Serialize all calls per instance (ISR included); CR1 / CR2 are read-modify-written. CCL-2 driver-library hand-off: this driver has no chip select, no transaction, no sleep entry and no device knowledge; the layer above it owns:  - Caller duty (CCL-2 SPI-01): when devices on one bus differ in CPOL/CPHA, bit order or    frame size, reconfigure the unit (SPI_Enable(0), SPI_Init, SPI_Enable(1)) before    asserting the chip select of each device.  - Caller duty (CCL-2 SPI-04b, SPI-05b): drive chip selects (GPIO, SPI_NSS_SOFT); release    CS on every exit path, including error returns of these services and the caller's own    timeout exits, and never assert a second CS while one is active.  - Caller duty (CCL-2 SPI-04c): send command, address and data of one device operation    inside one CS assertion; do not use nss_pulse=1 for devices that end an operation on    CS high.  - Caller duty (CCL-2 SPI-06b): in master mode the clock runs only while TX data is sent;    write one dummy frame (SPI_TryWrite8/16) for every frame to be received, or program    the TX DMA channel for the same count.  - Caller duty (CCL-2 SPI-11b): in full-duplex DMA program the RX and TX channel counters    from the same length value.  - Caller duty (CCL-2 SPI-22): SPI_DmaConfig(enable=1) returns BUSY while SPE=1 and    BSY=1; do not reprogram the DMA channels before both channels of the previous transfer    completed and the stop order (see SPI_DmaConfig) was run.  - Caller duty (CCL-2 SPI-10d): SPI_TryRead8/16 return ERR_HW while CRCERR is set (flag    kept); with crc_enable=1 and a DMA transfer read SPI_GetErrors after the CRC frame; on    CRCERR clear it with SPI_ClearCrcError and report a failure to the upper layer.  - Caller duty (CCL-2 SPI-23): before a latch/strobe pulse wait for FTLVL=0 and BSY=0    (SPI_GetFifoLevels, SPI_Status); TXE alone means the last frame is still shifting.  - Caller duty (CCL-2 SPI-15a): this driver never enters a low-power mode; before WFI/WFE    make sure no transfer runs (FTLVL=0, BSY=0, DMA channels stopped) and CS is high.  - Caller duty (CCL-2 SPI-13a, SPI-13b, SPI-13c): the device driver sends the write enable    command in its own CS cycle before each write/erase, polls the device busy status (or    waits a fixed time) before the next command, and splits writes at the device page    boundary.  - Caller duty (CCL-2 SPI-14a, SPI-14b, SPI-14c): the device driver checks the device ID    at start-up, rejects all-0x00/all-0xFF reads (or uses a CRC or known field), and    verifies any checksum field the device sends before using the data.  - Caller duty (CCL-2 SPI-15c): the device driver sends the device power-down command    before MCU sleep and the wake-up command before the first access after wake-up. Contract: Docs/v0.11_SPI_CONTRACT.md.

## stm32g4_tim.h

General-purpose, advanced and basic timer driver (RM0440 Rev 9 sections 29..32): TIM1/8/20 (advanced), TIM2/5 (32 bit), TIM3/4, TIM6/7 (basic), TIM15, TIM16, TIM17 (instances SKU-guarded). The v0.10 extension (counter mode, encoder, complementary outputs, break / dead time, flags, TRGO) is compiled only with the full CMSIS header (TIM_SPL_EXTENDED). Common rules: non-blocking, no static state, no interrupt handlers installed; invalid timer or argument -> SPL_ERR_PARAM and a rejected state -> SPL_ERR_STATE, both with no register write (exception: TIM_BreakDeadTimeInit LOCK read-back). Read-only getters and TIM_ClearFlags (single write) are ISR-safe. Issue #27 policy: ARR and CCRx are independent, CCR > ARR is valid (PWM: OCxREF held, OC: no match in the period). In that case the other BDTR fields WERE written (LOCK 0 locks nothing): an exception to "no write on error", kept visible instead of silently returning OK. ## stm32g4_vrefbuf.h

Voltage reference buffer (VREFBUF, RM0440 Rev 9 section 23). Single instance, no static state, no waits. CMSIS defines VREFBUF on G431, G474, G491 and G4A1 but not on G411xB or G414: there every function returns SPL_ERR_UNSUPPORTED without any access. Usage: RCC SYSCFGEN on -> VREFBUF_SetScale (ENVR = 0) -> VREFBUF_SetMode(INTERNAL) -> poll   VREFBUF_ReadyStatus until OK. VREFBUF_GetTrim reads the factory trim at any time. Common rules: CSR writes are read-modify-write of the rw fields only; not concurrency-safe. Caller duties (all APIs):  - APB2 clock: RCC_APB2ENR.SYSCFGEN (SYSCFG + COMP + VREFBUF + OPAMP).  - VREF+ pin conflicts, per mode that acts on the pin (CCL-2 ANL-09; the    driver cannot detect the package or the board):    INTERNAL (buffer drives VREF+) and OFF_PULLDOWN (VREF+ pulled to VSSA):    never on packages where VREF+ is double-bonded with VDDA (RM0440 23.1:    the buffer would fight VDDA, the pull-down would load it), and never    while an external reference or any other source drives VREF+ (two    sources on one pin / the pull-down loads that reference). Allowed only    with VREF+ connected to its decoupling capacitor alone.    EXTERNAL (reset) and HOLD: VREFBUF does not drive VREF+.  - Minimum VDDA per scale: device datasheet (RM0440 23.2 note a). Contract: Docs/v0.11_VREFBUF_CONTRACT.md.

### `VREFBUF_SetScale`

```c
SPL_Status VREFBUF_SetScale(uint32_t scale);
```

VRS write. PARAM: scale > 2. STATE: ENVR=1 (RM0440 23.4.1 note). Hardware reloads the factory TRIM for the new scale (RM0440 23.3).

- Caller: VDDA must meet the minimum for the new scale (datasheet); serialise CSR writers.
- Level: `PARAM[F] STATE[r] UNSUPPORTED[r]`

### `VREFBUF_SetMode`

```c
SPL_Status VREFBUF_SetMode(uint32_t mode);
```

Writes ENVR and HIZ in one CSR write, VRS kept. Enable = INTERNAL, disable = EXTERNAL. After INTERNAL poll VREFBUF_ReadyStatus.

- Caller: INTERNAL and OFF_PULLDOWN only where the file-header VREF+ pin rules allow them (package and board are not readable; CCL-2 ANL-09); poll VREFBUF_ReadyStatus before using the reference; serialise CSR writers. ERRATA ES0430 2.8.1 (G47x/G48x only; removed for G491/G4A1 in ES0523 Rev 2): GPIO toggling on PB10/PB11/PB13/PB14/PD14 (Rev Z/Y) or PB10/PB13 (Rev X) disturbs VREF+ in INTERNAL mode; keep them low.
- Level: `PARAM[r] UNSUPPORTED[r]`

### `VREFBUF_ReadyStatus`


OK: VRR=1 in INTERNAL mode. BUSY: INTERNAL mode, VRR=0 (poll again). STATE: ENVR=0 (never ready) or HOLD mode (VRR detection disabled).

- Caller: bound the polling loop; the settling time is in the datasheet.

## stm32g4_wwdg.h

System window watchdog driver (WWDG, RM0440 Rev 9 section 36). Scope: the single WWDG instance; timeout helper without register access. Usage: WWDG_CalcTimeoutUs, WWDG_Config, WWDG_Enable, then (EWI used) WWDG_ClearEarlyWakeupFlag and the NVIC enable; WWDG_Refresh inside the window from the main loop. Common rules: no function waits; no static state; no clock is enabled here; the library itself never refreshes. Activation (WDGA) is irreversible until reset; EWI cannot be cleared by software. Caller duties (all APIs):  - Clock: WWDG APB clock (RCC) enabled first.  - Refresh policy: see WWDG_Enable (CCL-2 WDG-11) and WWDG_Refresh (CCL-2 WDG-02a, WDG-02b,    WDG-08, WDG-10). Contract: Docs/v0.10_WDG_CONTRACT.md.

### `WWDG_Config`

```c
SPL_Status WWDG_Config(uint32_t timebase, uint32_t window, uint8_t ewi);
```

CFR: timebase WDGTB 0..7, window 0x40..0x7F, ewi 0/1. ERR_STATE if EWI is already set and ewi=0 (EWI is set-only).

- Caller: pick timebase and window from WWDG_CalcTimeoutUs for the actual PCLK1 (the window/counter relation is not checked, see WWDG_Refresh).
- Level: `PARAM[F] STATE[r]`

### `WWDG_Enable`

```c
SPL_Status WWDG_Enable(uint32_t counter);
```

Irreversible: CR = WDGA | counter (0x40..0x7F); the WWDG runs until reset. ERR_STATE if already active.

- Caller: every operation without refresh after WWDG_Enable must be shorter than the timeout computed for the actual PCLK1; otherwise refresh inside it or enable the WWDG after it.
- Level: `PARAM[F] STATE[r]`

### `WWDG_Refresh`

```c
SPL_Status WWDG_Refresh(uint32_t counter);
```

Reload counter (0x40..0x7F). ERR_STATE if not active or if the current counter is above the window (a write now would reset the MCU).

- Caller: call WWDG_Refresh only from thread context, never from an interrupt handler (EWI included) or a callback run by one, and only in the main (task) loop or inside a long multi-page/multi-block processing loop, never in delay, driver or helper functions. with several tasks or a cyclic schedule, refresh only after every critical task has reported progress in the last refresh interval, or only after a common cycle that called all critical tasks unconditionally has completed in that round. choose a window below the reload counter and time each refresh after the counter drops below the window; an early refresh is rejected (ERR_STATE) but the window/counter relation is not checked.
- Level: `PARAM[F] STATE[r]`

- Caller: none beyond the file-header duties.
